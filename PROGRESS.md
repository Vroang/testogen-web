## Текущий шаг: 7 — библиотека учебников + загрузка файлов
## Статус: шаг 7 выполнен

## Что сделано (шаг 7)
- Подключены библиотеки pdfjs-dist 6.3.289 (PDF) и mammoth 1.12.3
  (DOCX) — единственные новые зависимости, разрешены заданием.
- Парсер учебников (src/lib/textbookParser.ts): извлечение текста
  постранично из PDF (pdf.js, worker через Vite ?url), DOCX через
  mammoth.extractRawText, TXT через FileReader; разбивка по разметке
  «§ N» (number, title — строка после § до переноса, до 100 символов,
  text, start_page — страница, где начинается §, end_page — страница
  перед следующим §; для DOCX/TXT всё = 1). Текст до первого §
  отбрасывается. Если § не найдены — понятная ошибка, загрузка
  не начинается.
- Экран /textbooks (вместо заглушки): шапка, «← На главную»,
  счётчик «Всего: N учебников», кнопка «+ Загрузить учебник»;
  карточки (название, «PDF · 25 параграфов · загружен 19 сентября
  2026», корзина), клик по карточке → /textbooks/:id; пустое
  состояние; загрузка/ошибка/«Повторить»; сортировка по uploaded_at
  desc.
- Загрузка: скрытый input (accept .pdf/.docx/.txt); проверка формата
  (тост «Неподдерживаемый формат»); размер >50 МБ → диалог «Файл
  слишком большой (X МБ)…»; индикатор «Обрабатываем файл…» с этапами
  и процентами (чтение 0-30, извлечение 30-60, разбивка 60-70,
  облако 70-100); UUID через crypto.randomUUID(); файл в Storage
  textbooks по пути userId/textbookId.ext (upsert); insert в
  textbooks; вставка параграфов пачками по 100; при ошибке вставки —
  откат (файл из Storage + запись учебника) и красный тост; успех —
  «Учебник загружен: N параграфов» и обновление списка.
- Экран /textbooks/:id: шапка «← Мои учебники» + название; метаданные
  + красная кнопка «Удалить учебник»; список параграфов «§ 4.
  Реформация», для PDF «стр. X–Y», превью 100 символов, тап — полный
  текст; удаление с диалогом «Все параграфы и файл будут удалены.
  Отменить нельзя.» → параграфы + учебник + Storage-файл → редирект.
- Удаление доступно и корзиной на карточке списка (тот же диалог).
- Проверено в браузере с моками REST и Storage (код не менялся):
  TXT e2e (3 параграфа, заголовки, страницы 1-1, текст до §
  отброшен); hand-crafted 3-страничный PDF → 3 параграфа со
  страницами 1/1, 2/2, 3/3 и превью; просмотр и раскрытие;
  удаление из просмотра и корзиной из списка (Storage + обе таблицы
  очищены); ошибка вставки параграфов → откат; формат .rtf → тост;
  файл 51 МБ → диалог про размер. Сборка без ошибок, тестовые данные
  убраны.
- Отправлено в GitHub (main).

## Известные проблемы
- Проверка ключа Supabase через curl давала «Invalid API key», однако
  пользователь подтвердил, что ключ валиден; реальный запрос из
  браузера проходит. Игнорируем.
- Сборка предупреждает о размере бандла ~500 kB — не критично,
  можно ускорить код-сплиттингом на шаге 9 (полировка).
- OpenRouter вызывается прямо из браузера — у OpenRouter CORS
  разрешён; если при реальном ключе браузер заблокирует запрос,
  понадобится небольшой прокси (решим по факту проверки).
- Реальные данные и реальная генерация проверяются с настоящим
  ключом OpenRouter; вся механика проверена с тестовыми моками.
