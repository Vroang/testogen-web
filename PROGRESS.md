  'manual', topic: пусто → null); created_at — серверный default.

  вопрос сверху за счёт сортировки created_at desc). Ошибка —

  правильный ответ выбран; красные ошибки под полями.

  fetch, код не менялся): кнопка на списке; форма пустая с «А» и
  «Средний»; создание (тема «Тест», правильный «Б», «Сложный») →
  toast «Вопрос создан» → вопрос первым в списке с метками
  «Сложный», «Вручную», «Тест» и зелёным «Б) ✓»; пустая форма →
  5 красных ошибок, ничего не сохраняется; «Отмена» возвращает без
  изменений; сценарий ошибки сети — красный тост, форма открыта

  ошибок. Тестовые данные и сессия убраны.

## Что сделано (шаг 0)

## Известные проблемы
- Проверка ключа Supabase через curl давала «Invalid API key», однако
  пользователь подтвердил, что ключ валиден; реальный запрос из
  браузера проходит. Игнорируем.
- Сборка предупреждает о размере бандла ~500 kB — не критично,
  можно ускорить код-сплиттингом на шаге 9 (полировка).
- Реальные данные проверяются при входе настоящим аккаунтом;
  весь интерфейс (список, фильтры, создание, редактирование,
  удаление) проверен с тестовыми данными.

## Заметки
- Инструменты установлены в пользовательские папки:
  Node — %LOCALAPPDATA%\Programs\nodejs,
  Git (Portable) — %LOCALAPPDATA%\Programs\Git.
- Прокси для GitHub настроен в %USERPROFILE%\.gitconfig
  (http://127.0.0.1:10808).
- В системном конфиге PortableGit заменён credential-helper-selector
  на store (селектор показывал невидимый диалог и puши зависали);
  токен GitHub — в %USERPROFILE%\.git-credentials.
- Tailwind v3 (tailwind.config.js + @tailwind). Сессия Supabase —
  в localStorage (persistSession включён по умолчанию).
- Тестовые сессии/данные подкладывались только временно в браузере
  (перехватчик fetch) и удалены после проверки; в коде их нет.
